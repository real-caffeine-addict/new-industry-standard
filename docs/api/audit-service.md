# Audit Service API

## POST localhost:8084/audit-events

Creates an audit event.

### Headers

| Header           | Required | Notes                                      |
| ---------------- |----------| ------------------------------------------ |
| X-Origin-Service | yes      | Temporary Phase 1 origin-service indicator |

### Request

| Field      | Type     | Required | Notes                                                                                                  |
| ---------- | -------- | -------: | ------------------------------------------------------------------------------------------------------ |
| userId     | number   |      yes | User responsible for the action                                                                        |
| projectId  | number   |      yes | Project context for the audit event                                                                    |
| action     | string   |      yes | CREATED, UPDATED, DELETED, UPLOADED, STATUS_CHANGED                                                    |
| targetType | string   |      yes | PROJECT, PROJECT_MEMBER, USER, CONTACT, COMPANY, PROJECT_COMPANY, DOCUMENT, DOCUMENT_REVISION, DOSSIER |
| targetId   | number   |      yes | ID of the entity affected by the action                                                                |
| occurredAt | datetime |      yes | When the business action occurred, ISO-8601 local datetime                                             |

### Example Request

```json
{
  "userId": 1,
  "projectId": 1,
  "action": "CREATED",
  "targetType": "DOCUMENT",
  "targetId": 2,
  "occurredAt": "2026-07-13T16:42:36"
}
```

### Response

Temporary plain text response containing the serialized audit event payload.

### Notes

* Phase 1 runs without authentication.
* Request validation is not yet implemented.
* `originService` is currently received from the `X-Origin-Service` header.
* `logged_at` is generated by the database when the audit event is stored.
* `occurredAt` represents the time of the original business action.
* Audit events are project-scoped. Non-delivery/system events must use the reserved SYSTEM/HQ project context.
* The current `summary` database column temporarily stores serialized event data.
* JSON/event-data storage will be revisited after the first Phase 1 flow is validated.

---

## GET localhost:8084/audit-events/{id}

Reads the stored audit event payload by audit event ID.

### Path Parameters

| Field | Type   | Required | Notes          |
| ----- | ------ |----------| -------------- |
| id    | number | yes      | Audit event ID |

### Example Request

```http
GET /audit-events/1
```

### Response

Temporary plain text response containing the stored audit event payload.

### Notes

* This endpoint is intended for early development verification.
* It is not the final audit query API.
* Future audit read APIs should support project, target, user, action, and time-based filtering.
